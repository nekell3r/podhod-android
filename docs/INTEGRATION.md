# Интеграция Android с общим backend

Клиент: Kotlin + Jetpack Compose, атомарный JSON-архив Android v1. Доменные правила находятся в JVM-модуле `core`, платформенные реализации — в `app`. iOS reference: commit `30d1060c54864d57d5d2313dcfcadbe53a953774`. Контракт: `../podhod-backend/docs/API.md`.

## REST и OAuth

- `GET /v1/config?platform=android` возвращает `podhod-android`; отсутствие platform сохраняет iOS.
- Public client `podhod-android`, redirect `dev.podhod.training://oauth/callback`, authorization code + PKCE S256 через системный браузер. Client secret отсутствует.
- Scopes: `openid offline_access schedule:read schedule:write workout:read workout:write`, audience `podhod-api`.
- `deploy/prepare.py` backend добавляет клиента в новый realm. `deploy/configure_mobile_identity.py` создаёт Android-клиент в действующем realm и, с `--telegram-config`, официальный Telegram OIDC broker. Запускается оператором в закрытом окружении, не приложением. Старый `configure_identity.py` выполняет более широкую первоначальную настройку.
- API URL — в игнорируемом `local.properties`. Токены — в зашифрованном файле с ключом Android Keystore. HTTP и редиректы REST-запросов запрещены.

Сначала `/profile` связывает архив с subject. Затем синхронизируются история, шаблон, недели, active и протеин. Каждая mutable-запись имеет отдельную revision и UUID request ID. Контрольная точка сохраняется атомарно вместе с архивом. После ответа проверяется, не изменил ли пользователь локальный ресурс. История отправляется до очистки active.

Конфликт двух изменений требует выбора. Перед выбором сохраняются локальная и серверная версии в приватном `conflicts/`. Выбор active запрещён, если он теряет выполненные подходы. Различающаяся завершённая история не перезаписывается.

`AccountWorkspaces` выбирает отдельный архив по проверенному subject. При выходе используется гостевой каталог; при повторном входе восстанавливается свой архив, без смешивания с уже существующим аккаунтом. Старые файлы сохраняются в `legacy-backups`; гостевой каталог после принятия данных аккаунтом меняется. Старые UI и sync после переключения не изменяют новый архив. Измерение предыдущей тренировки закрывается при переключении, поэтому время другого пользователя остаётся неизвестным.

## Даты и время

Даты — `YYYY-MM-DD`, начало недели — понедельник, timestamps — ISO8601 UTC. Android создаёт события с миллисекундной точностью для совместимости с iOS. Часовой пояс архива используется для календаря, текущий пояс устройства — для уведомлений.

Телефон измеряет время. Длительности вычисляются из интервалов; истёкший отдых обрывается по deadline. Перед удалённой командой закрывается прежний локальный контекст. Для старой истории без timing время остаётся неизвестным, его нельзя выводить из настроек отдыха.

## Каталог и видео

`catalog/exercise-catalog.json` включается в assets напрямую; второй редактируемой копии нет. Версия, backend revision и SHA-256 закреплены в `catalog.lock.json`; проверка — `scripts/verify_catalog.py`. Aliases не переписывают сохранённые ID и заметки.

Плановая нагрузка: прямые подходы + косвенные × 0,5. Мышцы дедуплицируются, основная имеет приоритет. Неразмеченные упражнения показываются отдельно. Все подходы считаются рабочими. Плановый расчёт не заменяет фактическую историю.

Media3 воспроизводит лицензированные HTTPS-потоки с авторством. `playback: external` открывается браузером, не передаётся плееру и не скачивается.
