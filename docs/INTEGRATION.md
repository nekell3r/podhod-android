# Интеграция Android с общим backend

Первый клиент должен покрыть уже существующие пользовательские сценарии:

1. Программа по конкретным неделям и повторяемому шаблону, редактор дня и библиотека упражнений.
2. Экран «Сегодня», начало/остановка тренировки, вес и повторы по подходам, оба вида отдыха и пропуск упражнения.
3. История, прогресс, фактическое время отдыха и время текущего упражнения.
4. Утренние и вечерние отметки протеина, местные уведомления в 09:30 и 21:30.
5. Карточки мышц и техники, native-видео либо внешний просмотр по полю playback.
6. Плановая нагрузка: прямые подходы + косвенные × 0,5, с явным отображением неразмеченных упражнений.

Сначала данные сохраняются локально. Синхронизация использует тот же REST API, пользовательский OAuth subject, revision/CAS и UUID request ID. Календарные даты передаются как YYYY-MM-DD, timestamps — ISO8601, weekStart всегда понедельник. Завершённая история неизменна. Изменение шаблона или недели не переписывает активную тренировку.

Вход — authorization code + PKCE S256 через системный браузер. Перед реализацией нужно зарегистрировать отдельный public Android OAuth-клиент, определить проверяемый redirect URI и согласовать конфигурацию платформы в backend. Существующий `/v1/config` сейчас описывает iOS-клиент; нельзя считать его готовой Android-конфигурацией. Confidential secret MCP-клиента в мобильное приложение не помещается.

Измерение времени принадлежит телефону. Фоновые интервалы опираются на сохранённые timestamps, а удалённые команды применяются при фактической синхронизации. Каталог и библиотека доступны без сети, видео требуют соединения. Каталог должен совпадать с закреплённым экспортом по SHA-256; его исправления могут менять плановые итоги, поэтому версия каталога входит в результат расчёта.

Выбор Android UI-стека, локальной БД и системы сборки остаётся отдельным этапом реализации. Этот репозиторий не вводит общую библиотеку клиента или новый слой абстракции заранее.
