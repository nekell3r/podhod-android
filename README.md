# Подход для Android

Нативное приложение на Kotlin и Jetpack Compose, Android 8.0+ (API 26). Общие программа, история и аккаунт с iOS через REST API.

Календарные недели и шаблон, редактор дня и своих упражнений, офлайн-каталог с техникой и видео, плановая нагрузка, запись подходов, два вида отдыха, пропуски, история, время и график рабочих весов. Утренние/вечерние отметки протеина и локальные напоминания в 09:30 и 21:30.

- [Общий backend, REST API и MCP](https://github.com/nekell3r/podhod-backend).
- [Рабочий клиент iOS](https://github.com/nekell3r/podhod-ios).
- [Контракт API](https://github.com/nekell3r/podhod-backend/blob/main/docs/API.md).
- [План интеграции Android](docs/INTEGRATION.md).

`catalog/exercise-catalog.json` — закреплённый экспорт основного каталога бэкенда. `catalog.lock.json` содержит версию, SHA-256 и Git-ревизию источника. В нём нет записей тренировок, аккаунтов, токенов или серверных credentials. Условия данных и видеоссылок — [CATALOG-LICENSE.md](CATALOG-LICENSE.md).

## Сборка и установка

Нужны Java 21, Android SDK Platform 35 и Build Tools 35.0.0. Android Studio необязателен.

```sh
cp local.properties.example local.properties
./gradlew :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
python3 scripts/release_local.py
```

В `local.properties` укажи `sdk.dir` и собственный HTTPS API в `podhod.apiUrl`. Без настройки используется фиктивный `https://api.example.com`; офлайн-функции доступны. Выпуск создаёт подписанный `build/releases/Podhod-<версия>.apk` и `release.json`, не публикует файлы и не меняет сервер.

Постоянный ключ первого выпуска и его параметры находятся в игнорируемой `.local/signing/`. Сохрани закрытую резервную копию: обновления нужно подписывать тем же ключом. Основной application ID — `dev.podhod.training`; debug — `dev.podhod.training.debug`. Обновляй APK поверх предыдущего: удаление приложения сотрёт локальные записи.

## Данные и вход

`core/` содержит модели и правила тренировки, календарь, время, каталог и политику конфликтов. Android UI, хранение, REST, OAuth и уведомления находятся в `app/`. Архив Android v1 сохраняется атомарно до обновления состояния экрана. Ошибка чтения или неизвестная версия блокирует перезапись. Локальный формат отдельно от iOS; данные между платформами передаются через API.

Вход по логину или через Telegram: системный браузер, authorization code + PKCE S256, public client `podhod-android`, redirect `dev.podhod.training://oauth/callback`. Telegram подключается как OIDC-провайдер Keycloak, его секрет не передаётся приложению. Нужны `/v1/config?platform=android` и регистрация клиента: см. [инструкцию backend](https://github.com/nekell3r/podhod-backend/blob/main/docs/DEPLOYMENT.md). Токены зашифрованы ключом Android Keystore и исключены из backup.

У каждого аккаунта отдельный локальный архив. Выход открывает гостевой режим; повторный вход восстанавливает программу, историю, протеин и незавершённую тренировку этого аккаунта. Старое сохранение копируется с резервной копией; уже связанный архив остаётся у своего subject. Гостевые данные можно принять при первом входе нового аккаунта; после этого создаётся новый гостевой каталог. Существующий архив аккаунта с гостевым автоматически не объединяется. Время другого пользователя остаётся неизвестным в прежней тренировке.

Экран аккаунта читает собственный профиль и связи из Account API Keycloak: показывает имя или логин, состояние Telegram и связанный идентификатор. ID ответа сверяется с API тренировок. Данные обновляются при открытии, возвращении из браузера, вручную и при ручной синхронизации; после выхода очищаются. Нужны audience `account` и только role scope `account:view-profile`, настраиваемые `configure_mobile_identity.py`. Изменение связей этим токеном запрещено.

Синхронизация использует revision/CAS и UUID request ID. История отправляется до очистки active. При конфликте — явный выбор и резервная копия обеих версий. Нельзя выбрать версию active, теряющую выполненные подходы. Для привязки Telegram к старой истории сначала войди по прежнему логину и открой привязку в настройках аккаунта.

Напоминания требуют разрешения на уведомления; точные 09:30/21:30 на Android 12+ — разрешения на будильники. Без него система может задержать уведомление, что указано в интерфейсе. Расписание восстанавливается после перезагрузки, обновления и смены часового пояса. Media3 воспроизводит лицензированные потоки; `playback: external` открывается на сайте автора.

Каталог включается в assets напрямую. Проверка: `python3 scripts/verify_catalog.py`. JVM UI-тесты работают через Robolectric без эмулятора. Сценарии и ограничения — [docs/QA.md](docs/QA.md).
